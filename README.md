# SREP на Русском
Bloated версия утилиты SREP. Разработанная в 2022 году SmokelessCPUv2, программа устраняет ограничения традиционных модификаций BIOS, позволяя устанавливать временные патчи через загрузочный USB-накопитель, что полезно для разблокировки расширенных настроек в прошивке OEM-производителя.

# В чем разница в сравнении с оригиналом
* Файл конфига больше не обязан иметь название "SREP_Config.cfg". Теперь патчер выбирает в качестве конфига первый найденный файл с расширением '.cfg'.
  </br>
  </br>
* Появился Русский перевод для сообщений на экране и в логе, вывод в лог был приспособлен для кодировки Unicode. Сами сообщения учащены, чтобы прогресс выполнения лучше отслеживался, и у пользователя не возникало мысли что программа зависла. Добавление "_ENG" в название файла конфига отключит вывод на Русском (например, "Abc.cfg" > "Abc_ENG.cfg").
  </br>Для версий до 0.2.4, вводить аргумент "ENG" нужно в Shell (например, "SREP.efi ENG"). Разрешается передавать "ENG" в .nsh.
  </br>
  </br>
* Тем же образом, можно включить логирование "_LOG", или ограничить вывод текста в консоль "_NOCON".
  </br>
  </br>
* Добавил 8 новых команд: NonamePE, HandleIndex, LoadGUIDandSavePE, LoadGUIDandSaveFreeform, UninstallProtocol, UpdateHiiPackageFormSet, SuppressIfPatcher, Skip.
  </br>В каких случаях могут быть полезны - далее.
  </br>
  </br>
* Добавил поддержку абстрактных знаков (regex) для использования в строке шаблона. Классы знаков доступны [по ссылке](https://gist.github.com/kaigouthro/e8bad6a2c8df6ff13b8716027a172dc0#3-character-types).
  </br>
  </br>
* По умолчанию, комбинация Patch - Pattern теперь заменяет все вхождения, а не только первое, которые соответствуют указанному шаблону.
  </br>Количество мест к нахождению с использованием Patch теперь может быть настроено на определённое число для одного шаблона. Прогресс поиска отображается на экране в виде полосы загрузки.
  </br>Старую реализацию Patch выделил в отдельную команду Fast<ins>est</ins>Patch.
  </br>Добавил промежуточный вариант - Op FastPatch. Из мета-знаков в нём есть только самый популярный - точка(.), что делает поиск гораздо быстрее Op Patch.
  </br>
  </br>
* Добавил игнорирование строк конфига включащие символ решетки "#". Применимо для написания комментариев в файле.

# Как использовать
1. Соберите исп. файл сами или загрузите со страницы релизов.
</br>Начиная с версии 0.2.4, сборка требует патча BaseTools в соответствии с [этим gist](https://gist.github.com/Maxinator500/8b3da71d1e8c12285ff826b292a1f8ab).
2. Распакуйте файл на накопитель и сделайте его загрузочным.
3. Создайте новый или скопируйте готовый конфиг в корень.
4. Запустите.

# Синтаксис для каждой из новых команд (с примерами)
Операция в "<...>" опциональна. Некоторые команды не требуют доп. параметров для работы (например, Exec).

    Op Команда
        <GUID или Cтрока или Число>
        # Команда LoadGUIDandSaveFreeform поддерживает до 2 "параметров".
        # В зависимости от наличия второго, выбирается режим работы.
        <GUID или Cтрока или Число>
    <Op Patch> или <Op FastPatch>  или <Op FastestPatch> 
        Аргумент 1
        Аргумент 2
        Аргумент 3
    <Op End>
    
    # Если драйвер ещё не в памяти.
    <Op Exec>

### Значение

    Команда : NonamePE, Patch, LoadGUIDandSavePE, UninstallProtocol и остальные
    GUID : GUID драйвера или протокола для поиска
    Строка : Название модуля из UI Section
    Число : Кол-во строк к пропуску для Op Skip, или EFI_HANDLE ID для Op HandleIndex
    Аргумент 1 : Offset, Pattern, RelNegOffset, RelPosOffset для Patch
    Аргумент 2 : Модификатор для Аргумент 1 (например, HEX шаблон)
    Аргумент 3 : HEX патч
    
# Добавленные команды
## LoadGUIDandSavePE, LoadGUIDandSaveFreeform
Загружают PE, RAW, FREEFORM секции модуля из Firmware Volume по GUID. Применимо когда у модуля нет имени, а Op LoadFromFV не использовать. Редко для патчей, так как в память загружается вторая копия модуля.
</br>Т.е. первая команда нужна для особых случаев когда у App, запуск которого инициирует вход в биос, нет секции UI.
</br>Что делает команды менее бесполезными, это сохранение секции модуля как файл на флешку. Может выручить когда ни один способ дампа не работает.
</br>Формат GUID как в UEFITool.
  <details>
  <summary><strong>LoadGUIDandSavePE</strong></summary>
    
  ```
  Op LoadGUIDandSavePE
  
  # Это SetupUtility
  FE3542FE-C1D3-4EF8-657C-8048606FF670
  ```

  </details>
  <details>
  <summary><strong>LoadGUIDandSaveFreeform</strong></summary>
    
  ```
  Op LoadGUIDandSaveFreeform
  
  # Это SmallLogo с section subtype RAW. GUID от File.
  63819805-67BB-46EF-AA8D-1524A19A01E4


  Op LoadGUIDandSaveFreeform
  
  # Это setupdata. У section subtype FREEFORM есть свой GUID, его тоже нужно указать, даже если они одинаковы.
  FE612B72-203C-47B1-8560-A66D946EB371
  FE612B72-203C-47B1-8560-A66D946EB371
  ```

  </details>

## NonamePE
Ищет секцию PE по GUID.
</br>Синтаксис как у LoadGUIDandSavePE, но область поиска RAM, вместо FV.

Работает таким образом, что сначала находятся все дескрипторы с поддержкой LoadedImageProtocol. Затем путь FvFile каждого модуля по порядку сравнивается с указанным в конфиге, а при совпадении цикл сравнения останавливается, функция возвращает ImageInfo модуля на котором сравнение дало успех.

## HandleIndex
Находит загруженные дескрипторы в RAM по их ID из handle dump, который можно получить через команды UEFI shell, а также в SREP.log при первом запуске HandleIndex со случайным численным параметром.

## UninstallProtocol
Находит все дескрипторы с заданным протоколом и по очереди удаляет из них этот протокол.
В случае провала, укажет порядковый номер дескриптора в буфере, у которого протокол удалить не удалось

## UpdateHiiPackageFormSet
С версии 0.2.4, позволяет заменить данные c типом EFI_HII_PACKAGE_FORMS по указателю (EFI_HII_PACKAGE_LIST_HEADER + sizeof(EFI_GUID)), которые выгружены в HII Database, на имеющиеся в Image Handle.
  <details>
  <summary><strong>UpdateHiiPackageFormSet</strong></summary>
    
  ```
  # С версии 0.2.5 больше не требует получение ImageInfo

  # Копирование данных из AodSetup Image Handle в exported Package List, с последующим обновлением HII Db
  Op UpdateHiiPackageFormSet
  E39AC631-48ED-445E-9042-55B34F405843
  ```

  </details>

## SuppressIfPatcher
Вызывает встроенное приложение, которое отменяет действие EFI_IFR_SUPPRESS_IF во всех загруженных Package List и Image Handle. Аргумент "_NOCON" не имеет эффекта на вывод в консоль этого приложения
  ```
  # Команда не принимает параметры, работает автономно от SREP
  Op SuppressIfPatcher
  ```

## Skip
Дает возможность пропускать указанное число команд (считаются только Op), если прошлая завершилась с успехом. Можно создавать простые логические цепочки.
  <details>
  <summary><strong>Skip</strong></summary>
    
  ```
  Op LoadGUIDandSavePE
  # SetupUtility
  FE3542FE-C1D3-4EF8-657C-8048606FF670
  Op Skip
  # Пропустить секцию конфига для систем Aptio
  4
  
  Op LoadGUIDandSavePE
  # EsaFull
  A2DF5376-C2ED-49C0-90FF-8B173B0FD066
  Op LoadGUIDandSavePE
  # AMITSE
  B1DA0ADF-4F77-4070-A88E-BFFE1C60529A
  Op LoadGUIDandSavePE
  # Setup
  899407D7-99FE-43D8-9A21-79EC328CAC21
  Op Skip
  # Это система Aptio, пропустить всё до конца файла
  32
  
  ...
  ```

  </details>
  
## FastPatch и Patch
С версии 0.2.3, добавление десятичного числа в строку вызова команды изменит поведение аргумента Pattern. Число означает лимит на поиск вхождений шаблона.
  <details>
  <summary><strong>Patch <ins>с параметром</ins>, принимается значение в пределах от 0 до 9</strong></summary>
    
  ```
  Op Loaded

  # Setup
  899407D7-99FE-43D8-9A21-79EC328CAC21

  # Установить лимит в 5 вхождений для Pattern
  Op Patch 5
  Pattern

  # Какой-то шаблон
  290201861.27
  ```

  </details>
  Помогает ускорить выполнение конфига, когда меры по улучшению шаблона поиска не эффективны, оставляя выражение недостаточно узким.
</br>
</br>
С версии 0.2.4, патч может включать знак точки(.). Если патч затрагивает нежелательные участки памяти, позволяет не жертовать сложностью шаблона. 
  <details>
  <summary><strong>Сохранение значения из исходного буфера</strong></summary>
    
  000000FFFF00030629020A82<ins>12</ins>066C1C00000F < Значение в памяти
  ```
  Op FastPatch
  Pattern
  000000FFFF00....29020A8212066C1C00000F < Шаблон и патч
  000000FFFF00....29020A8247066C1C00000F   FormId 0x0603 не указано в конфиге
  ```
  000000FFFF00030629020A82<ins>47</ins>066C1C00000F < Новое значение в памяти с сохраненным FormId

  </details>

# Важные исправления
Версия 0.1.8. Исправлена ошибка, из за которой перед каждой следующей командой патча (Op Patch), массив хранящий смещения найденных вхождений шаблона не очищался. Самый последний "Op Patch" всегда заменял абсолютно все вхождения, которые были найдены за сеанс работы SREP.

Версия 0.2.2. Исправлена ошибка в Patch, при котором абстрактные символы в строке шаблона рассматривались как неподдерживаемые.

Версия 0.2.5. Исправлена EFI_INVALID_PARAMETER при вызове LoadFromFV, Получение .rsrc через HiiDatabase->ExportPackageLists изменено на способ с заголовком DOS (EFI_UNSUPPORTED). HiiForceLoad и SendForm удалены в пользу отдельного приложения.
